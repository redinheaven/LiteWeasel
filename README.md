# Lite_weasel —— 给老电脑用的丝滑小狼毫

**Lite_weasel** 是 [小狼毫（Weasel）](https://github.com/rime/weasel) 的一个改良版。小狼毫是 Windows 上的 Rime 输入法。

这个版本只想解决一个问题：**让小狼毫在老旧、低配的笔记本上打字也顺滑。**

## 为什么要做这个？

在 ThinkPad X220、X1 Carbon 5 代这类老机器上用小狼毫，常会遇到这些情况：

- 在新打开的程序里打第一个字时，**候选框要顿一下才出来**
- 打字快的时候，**候选框跟不上，感觉粘手**
- 输入法后台在更新词库时，**打字明显变卡**
- 偶尔输入法"卡住"，**连带正在用的软件一起没反应**

原因主要有这几个：

1. 输入法会被"装进"你打开的每个程序里。它画候选框时可能会拉起显卡驱动，这个驱动又大又慢。
2. 输入法后台进程抢不到 CPU。
3. 程序和输入法后台之间"传话"时，如果后台忙，前台只能干等。

## 我们做了什么（及计划做什么）

> **重要说明**：下面所有"快了多少"的数字，都是在一台**配置很好的台式机**上测的，**还没有在老笔记本上测过**。老机器上效果如何，要等实测。

| 改进 | 用大白话说 | 状态 |
|---|---|---|
| 候选框用 CPU 画（不动用显卡驱动） | 上游小狼毫本来就这样做；我们只验证了在记事本里确实只加载软件渲染组件，没有系统性检查其他程序 | ✅ 沿用，未改动 |
| 候选框画得更省力 | 去掉了一个只在调试时才有用的检查，每次重绘的时间从约 3.4 毫秒降到约 1.7 毫秒 | ✅ 已完成（台式机实测） |
| 提前准备好绘制环境 | 一到输入框就提前把候选框要用的绘制环境准备好，新程序里第一个字的处理时间从约 36 毫秒降到约 19 毫秒；代价是每个程序多占约 4MB 内存，第一次切到它时会多等约 17 毫秒 | ✅ 已完成（台式机实测） |
| 防止输入法拖死程序 | 后台输入法服务卡住时，不再让正在用的程序一直干等：每次最多等约四分之一秒，连续没反应就暂时放弃，按键直接当英文字母打出来，后台恢复后自动回来。模拟卡住 4 秒，程序被卡的时间从"一直卡到恢复"降到合计不到 1 秒 | ✅ 已完成（台式机模拟验证） |
| 提高输入法后台的优先级 | 让输入法优先拿到 CPU，更新词库时则主动让路 | 📋 还没做，要先测量部署期间打字的情况 |
| 更多提速 | 我们发现新程序里第一个按键在后台的耗时取决于你的词库大小（一台机器上从 0.3 毫秒到近 9 毫秒），还没查清是哪一部分造成的；另外每个按键都先确认一次后台在不在，也想精简 | 📋 等笔记本上的实测数据再决定 |

**使用这个版本时你会遇到的变化**：
- 后台输入法服务**卡住的时候**，输入法会暂时"消失"，你打的拼音字母会直接变成英文字母出现在文档里；后台恢复后（一般几秒内）自动恢复，不需要手动操作。
- 装这个版本之后，输入法后台**第一次启动会重新部署一次**你的词库配置（只是重新生成缓存，你的词库和配置不会被改动）。
- 这个版本**没有签名**，是用来测试的版本，不是正式发行版。

详细进展、数据和遇到的坑见 [`PROGRESS.md`](PROGRESS.md)。

## 你自己现在就能做的提速小技巧

这些不需要等新版本：

1. **关掉候选框阴影**：在配色方案里把 `shadow_radius` 设成 `0`。阴影是 CPU 绘制，理论上在老电脑上更耗时（**我们还没有实测过它的开销**，这是建议，不是测量结果）。
2. **让杀毒软件放过输入法**：在 Windows 安全中心把 `%APPDATA%\Rime` 和小狼毫的安装目录加进"排除项"（同样是建议，没有实测）。
3. **精简输入方案**：少挂几个词库，关掉用不上的 Lua 脚本、emoji 和繁简转换，每页候选数也别设太多。我们实测过一个现象：同一台电脑上，新程序里第一个按键在后台的耗时，在用户的真实词库配置下约 8 毫秒，换成干净的标准词库只要约 0.3 毫秒（具体是自定义词库、用户词库还是别的造成的，还没查清）。

## 安装和编译

本项目的编译方式和原版小狼毫一样，请参考 [`INSTALL.md`](INSTALL.md)。需要 Visual Studio 2022、Boost 和 librime。
